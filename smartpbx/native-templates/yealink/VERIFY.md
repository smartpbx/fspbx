# Yealink native templates (patchbay#4352, slice yealink)

Templates: `t4-smartpbx` (T46U/T48U/T43U/T41S/T46S, and T57W because stock T5 == stock T4), `t44u-smartpbx` (T44U), `t3-smartpbx` (T33G/T31G).
Cloned from stock T4/T3 v1.0.20 by `.tpl` patch only; nothing was loaded into the DB. Evidence: `~pbx/native-render/render.sh` (legacy y-files + `<mac>.cfg` concatenated, vs `--native --template-file`), compared key by key (compare.sh on the same files gives 550-950 raw lines per device because legacy writes every unused account block and native every unused key slot; the table below is the filtered view, unused account/linekey/expansion slots dropped, true/1 treated equal). Render output held only in `/tmp/p4352-yealink.*` on fspbx01 and deleted.

## Provisioning URL and rollback
Rendered in all three templates: `static.auto_provision.server.url = <yealink_provision_url>`; when that setting is unset OR an empty string, it falls back to the literal `https://provision.smartpbx.io/app/provision/`, which is the value of the legacy default setting `yealink_provision_url` (the legacy templates have no fallback of their own: they print `{$yealink_provision_url}`), never `provision_base_url` (the controller always sets that to `/prov/`). Assigning the template alone therefore never moves a phone.
- Cutover: set the device setting `yealink_provision_url` = `https://<host>/prov/` and set `device_template_uuid`; the phone adopts the URL on its next pull.
- Rollback: set the device `yealink_provision_url` back to the legacy URL (template still assigned), wait one pull, then clear `device_template_uuid`. Blanking the setting also lands on the legacy URL.
- Evidence (re-run after review, T46U 100171, T44U 105353, T33G 102905; the override/empty/unset cases force the setting in memory by prepending a `@php` line to a temp copy of the template, no DB write): default setting renders `https://provision.smartpbx.io/app/provision/`; override `https://portal.smartpbx.io/prov/`; empty and unset both render `https://provision.smartpbx.io/app/provision/`. Unset-setting native render vs the legacy y-file line, byte compared on all three devices (T46U 44dbd27aaa06, T44U 44dbd2f983f1, T33G 44dbd2724503): IDENTICAL.

## Changes versus stock T4/T3
1. URL from setting (above). 2. `user_name` = user id (legacy); `yealink_user_name_with_domain=1` restores stock `id@server`. 3. `outbound_proxy_enable = 1` whenever a proxy exists (`yealink_outbound_proxy_disable=1` opts out; ports from `outbound_proxy_N_port` like legacy). 4. Remote phonebook: native phonebooks when assigned, otherwise the legacy Users/Groups/Extensions URLs (`/app/provision/?file=directory.xml&contacts=...`, creds embedded URL-encoded (legacy embeds them raw; a password with `@ / ? #` breaks the raw form, so this is a deliberate difference), `features.remote_phonebook.enable` from `yealink_remote_phonebook_enable`, default 0 as legacy) plus `static.directory_setting.url` (favorites). Identical to legacy on T46U. 5. Softkey 1 "Xfer to VM" and Intercom key: Intercom on `programablekey.3` and `programablekey.2.type=0` exactly as legacy `y900000000108.cfg` (T46U); `yealink_intercom_key_slot` (0 disables, 2 = stock), `yealink_xfer_vm_softkey_disable`. 6. Wallpaper from `yealink_*_wallpaper(_filename)` with legacy isset semantics. 7. `called_party_info_display=1`, `auto_blf_list_enable=1`, `blf_list_sequence_type=1`, `dnd.emergency_enable=1`, `blf.enhanced.idle.enable=0`, `predial_autodial=1` (legacy hard-codes 1; stock rendered it empty), `session_timer.enable` cast to int. 8. T44U only: `subscribe_mwi` from setting default 0, `udp_update_enable 3`, `udp_update_time 30`, account `sip_trust_ctrl 1`, `tls_cipher_list`, `notify_reboot_enable 0`, `hold_or_swap 0`, `mail_power_led_flash 1`, `local_directory 1`, `voice.cng/vad` from settings.
9. **All echoes are raw (`{!! !!}`), not `{{ }}`.** Stock `{{ }}` HTML-escapes `& ' < >`: a tenant's `http_auth_password` containing `&` rendered as `&amp;` natively, so the phone would get a wrong provisioning password (seen on 100171, fixed here). The same applies to SIP passwords and display names with `'` in stock T4/T3/T5/T7/T4W and probably every native template: **separate fix needed in the stock templates**.
10. Boolean-typed settings with value 0 cast to `false` and render as an empty value in stock (e.g. `yealink_session_timer`, `predial`); only the two above are guarded.

## Known, not changed
Linekey and expansion placement follows iteration order (`$slot++`), as in stock T4/T3, not key id; it matches legacy on the 17 sampled devices. A key template with gaps in key ids would shift later keys, and the renderer does not clamp to 30 keys. This belongs to the key-mapping owner (profiles slice, and #12's blank-row handling), not to these templates.
